RepCRec Design & Compliance Report

Course: Advanced Database Systems  |  Date: 2025-12-07  |  Authors: Xi Wang, Sihang Zhao

Executive Summary

This report presents the RepCRec implementation against handDB2-4-11 §4.1 and Requirment.txt. The system delivers SSI over MVCC, Available Copies replication, failure/recovery with stale flags, English-only documentation, and explicit function headers (purpose/inputs/outputs/side effects). Recent fixes enforce continuous-uptime checks for replicated reads, abort on write-site failure before commit, provide the querystate() command, and keep required outputs aligned with the grading format.

System Overview

  • 20 variables (x1..x20), 10 sites. Even variables replicated to all sites; odd variables at site 1 + (i mod 10); initial value 10*i.
  • Concurrency control: Serializable Snapshot Isolation via WW first-committer-wins and RW intersection checks.
  • Replication: Available Copies (ROWAA); commit-time broadcast to available replicas.
  • Failure model: site fail/recover; stale-flag on replicated copies until a fresh commit.

Architecture & Components

  • TransactionManager: central, never fails; tracks transactions, sites, failure history, SSI validation, failure-driven aborts.
  • Site: holds replicas; stale-flag recovery; per-replica readability.
  • VariableCopy: MVCC versions; snapshot returns (value, commit_ts) for uptime validation.
  • Transaction: read/write sets, write-target sites, waiting state, write-after-fail flag.
  • Parser/main: command parsing/dispatch; commands: begin, beginRO, R, W, end, fail, recover, dump, querystate.

Algorithmic Design

MVCC Snapshot Read

  • Selects latest committed version with commit_ts < txn.start_ts; returns value + commit_ts.
  • Read-your-own-write served from the workspace.

Available Copies & Uptime Validation

  • Odd variable: read its sole hosting site; wait if down.
  • Even variable: require a replica that stayed UP from version commit_ts to txn.start_ts. If all replicas fail this window, abort; otherwise wait when none are currently readable (e.g., stale after recovery).
  • Writes are deferred; commit propagates to all available hosts.

SSI Validation

  • WW conflict: first-committer-wins, abort on overlapping writes committed after txn start.
  • RW conflict: abort on intersections of (txn.read_set, committed.write_set) or (txn.write_set, committed.read_set) for commits after txn start.

Failure & Recovery

  • Write-after-fail rule: if any site planned for a write fails pre-commit, end() aborts.
  • Stale-flag: replicated copies unreadable after recovery until a new committed write; non-replicated copies readable immediately.
  • Failure history underpins uptime validation for replicated reads.

Required Outputs (grading format)

  • Dump: every dump() prints committed values of all variable replicas at all sites, one line per site, variables sorted ascending by name; down sites are still printed and do not reflect writes while down. Example: site 1 – x2: 6, x3: 2, ... x20: 3.
  • Reads: every read prints the value read, e.g., x4: 5.
  • Transaction results: every end(T) prints T1 commits or T1 aborts.
  • Other events: on commit/abort print transaction name; on write indicate affected sites (those up at commit); when a transaction waits due to a site failure (e.g., odd variable on a down site), print the wait event.

Testing Strategy

Existing scripts: test_basic.txt, test_ww_conflict.txt, test_rw_conflict.txt, test_site_failure.txt, test_replicated.txt, test_snapshot.txt, test_readonly.txt, test_comprehensive.txt.

Recommended additional cases with expected outcomes:

  • All replicas down between last commit and txn start for an even variable → abort on read.
  • Txn writes; a written site fails before commit → abort at end(T).
  • Recovering site for replicated vars remains unreadable until a new commit arrives.
